# Self Prompt – Админские списки и личная комната пользователя

## Цель
Реализовать REST-эндпоинты для получения текущей комнаты пользователя и админского списка активных/ожидающих комнат, предоставить администраторам полный перечень пользователей с расширяемыми данными, а также перевести README на русский язык.

## Контекст
- Комнаты управляются `RoomService`, который уже покрывает создание, выход и проверку доступа. Необходимо расширить сервис методами выборки текущей комнаты и списка активных комнат. 【F:apps/api/videochat_api/services/rooms.py†L25-L220】
- Маршруты комнат реализованы в `api/endpoints/rooms.py`, а зависимость `get_current_user` предоставляет текущего пользователя. Для админских операций понадобится проверка `is_admin`. 【F:apps/api/videochat_api/api/endpoints/rooms.py†L1-L170】【F:apps/api/videochat_api/dependencies.py†L19-L118】
- В `User` отсутствует флаг администратора и нет эндпоинта списка пользователей; поиск реализован в `api/endpoints/users.py`. 【F:apps/api/videochat_api/models/user.py†L1-L24】【F:apps/api/videochat_api/api/endpoints/users.py†L91-L132】
- Документация (`apps/api/README.md`) частично на английском, необходимо привести к единому русскому стилю и описать новые маршруты.

## Проблема
- Пользователь не может узнать, находится ли он сейчас в комнате, без знания конкретного UUID и вызова `GET /rooms/{room_id}`.
- Администраторы не имеют возможности увидеть все активные и ожидающие комнаты, что усложняет мониторинг и модерацию.
- Нет способа получить полный список пользователей и их артефактов (устройства, сессии); отсутствует контроль доступа для админов.
- README содержит англоязычные разделы и не отражает новые обязанности администратора.

## Предлагаемое решение
1. Добавить в модель `User` поле `is_admin`, миграцию и зависимость `get_current_admin_user`, возвращающую 403 для неадминов.
2. Расширить `RoomService` методами `get_current_room_for_user` и `list_active_rooms`, создать маршруты `GET /rooms/me` и `GET /rooms` (только для админов).
3. Реализовать `GET /users` с параметром `include` (`devices`, `sessions`) и новыми схемами `UserListResponse`, `UserDevice`, `UserSession`.
4. Обновить тесты комнат и пользователей, чтобы покрыть новые сценарии, и локальную документацию (README, knowledge) на русском языке с описанием функционала.

## Проверка
- Запустить `pytest` внутри `apps/api`, убедившись, что покрыты сценарии комнат и админских эндпоинтов.
- Провести ручной сценарий: создать комнату, проверить `GET /rooms/me`, авторизоваться админом, вызвать `GET /rooms` и `GET /users?include=devices&include=sessions`.

## Риски и открытые вопросы
- Списки пользователей и комнат могут стать тяжёлыми при большом количестве записей — возможно, потребуется пагинация и фильтры.
- Расширенный доступ к данным доступен только администраторам; необходимо синхронизировать процесс назначения `is_admin` с бизнес-требованиями.
