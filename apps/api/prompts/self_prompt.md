# Self Prompt – 500 на /auth/me после добавления is_admin

## Цель
Исправить ошибку 500 при вызове `GET /auth/me`, чтобы эндпоинт корректно возвращал данные текущего пользователя с признаком администратора.

## Контекст
- Аутентификация реализована в `api/endpoints/auth.py`, где `read_current_user` возвращает объект `UserResponse`. 【F:apps/api/videochat_api/api/endpoints/auth.py†L231-L279】
- Pydantic-схема `UserResponse` описана в `videochat_api/schemas/auth.py` и теперь содержит поле `is_admin`, сериализуемое как `isAdmin`. 【F:apps/api/videochat_api/schemas/auth.py†L1-L64】
- Модели пользователей хранятся в SQLAlchemy и проксируются через `get_current_user` из зависимостей. 【F:apps/api/videochat_api/dependencies.py†L48-L118】
- README и AGENTS подчёркивают необходимость поддерживать совместимость с текущими клиентами и обновлять схемы при изменении моделей. 【F:apps/api/README.md†L1-L235】【F:apps/api/AGENTS.md†L1-L43】

## Проблема
- После добавления поля `is_admin` схема `UserResponse` использует alias `isAdmin` только для валидации входных данных.
- При валидации ORM-объекта Pydantic ожидает атрибут `isAdmin`, которого нет в модели `User`, из-за чего возникает ValidationError и FastAPI возвращает 500.
- Клиенты получают "Internal Server Error", хотя авторизация проходит успешно.

## Предлагаемое решение
1. Обновить `UserResponse`, чтобы она принимала как `is_admin`, так и `isAdmin` при валидации, но продолжала сериализовать поле как `isAdmin`.
2. Дополнительно убедиться, что `model_dump(by_alias=True)` выдаёт ожидаемую форму для фронтенда.
3. Добавить/обновить автотест, проверяющий успешный ответ `GET /auth/me` и отсутствие 500 после изменений.
4. При необходимости зафиксировать в документации, что поле администратора теперь присутствует в ответе.

## Проверка
- Запустить юнит/интеграционный тест, покрывающий `GET /auth/me`.
- Выполнить ручную проверку через тестовый клиент FastAPI или cURL, убедившись, что ответ 200 OK и JSON содержит `isAdmin`.

## Риски и открытые вопросы
- Нужно подтвердить, что клиенты, использующие старое имя `is_admin`, не сломаются; возможно, потребуется временная поддержка обоих вариантов.
- Следует убедиться, что аналогичные alias-изменения в других схемах не создают похожих ошибок.
