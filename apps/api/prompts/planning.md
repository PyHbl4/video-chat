# Планирование задач
1. Прочитайте актуальные `README.md`, `AGENTS.md` и файлы в `knowledge/`, чтобы понимать устройство FastAPI, Socket.IO и ограничения окружения.
2. Локализуйте кодовую базу перед изменениями:
   - REST — `videochat_api/api/endpoints/*` и схемы в `videochat_api/schemas/*`.
   - Доменная логика — `videochat_api/services/*` (auth, дружба, комнаты, presence, rate limiting).
   - Модели и миграции — `videochat_api/models/*`, `alembic/versions/*`.
   - Вебсокеты — `videochat_api/websocket/server.py` и адаптер `videochat_api/asgi.py`.
3. Сверьте поведение с существующими тестами в `tests/`. Если сценарий не покрыт, добавьте тест перед изменениями.
4. Планируя работу, учитывайте влияние на Redis, Socket.IO и кэш комнат: при изменении контрактов обновляйте emit-события и документацию.
5. После реализации обновляйте README, `knowledge/` и соответствующие подсказки `prompts/`, если меняется публичное поведение.
6. Обязательные проверки: `pytest` (из `apps/api`) и ручной сценарий комнаты из README при изменениях, затрагивающих дружбу/комнаты/аутентификацию.
