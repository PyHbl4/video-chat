# Self Prompt – rooms listing fix

## Цель
Обновить эндпоинт `GET /rooms/me`, чтобы он возвращал все комнаты текущего пользователя (ожидающие и активные) с идентификаторами `room_id`, устранив ошибку 404 при наличии приглашения.

## Контекст
- Приложение `apps/api` реализовано на FastAPI, управляет аутентификацией, дружбой и комнатами. 【F:apps/api/README.md†L1-L106】
- Роутеры комнат находятся в `videochat_api/api/endpoints/rooms.py`; бизнес-логика инкапсулирована в `RoomService`. 【F:apps/api/videochat_api/api/endpoints/rooms.py†L1-L220】【F:apps/api/videochat_api/services/rooms.py†L1-L320】
- Текущее руководство по комнатам описывает ручные шаги проверки и ожидает, что `GET /rooms/me` покажет состояние комнаты. 【F:apps/api/knowledge/rooms.md†L1-L37】

## Проблема
- При создании комнаты в `RoomService.create_room` участником становится только инициатор; приглашённый пользователь не получает записи в `room_participants`, пока не выполнит `join`. 【F:apps/api/videochat_api/services/rooms.py†L49-L118】
- Эндпоинт `GET /rooms/me` полагался на выборку активных участников и не учитывал приглашения, из-за чего пользователи видели 404 даже при наличии ожидающей комнаты. Сценарий воспроизводится в ручной проверке — приглашённый не видит комнату до присоединения. 【F:apps/api/knowledge/rooms.md†L19-L33】

## Предлагаемое решение
- Добавить в модель и БД поле `rooms.target_user_id`, чтобы явно хранить идентификатор приглашённого пользователя. 【F:apps/api/videochat_api/models/room.py†L26-L71】
- Реализовать в `RoomService` метод `list_rooms_for_user`, который объединяет активные участия и ожидающие приглашения по `target_user_id`. 【F:apps/api/videochat_api/services/rooms.py†L181-L248】
- Перевести эндпоинт `/rooms/me` на новый метод и изменить схему ответа на список комнат (`RoomsListResponse`). 【F:apps/api/videochat_api/api/endpoints/rooms.py†L130-L138】
- Обновить кеширование, документацию и тесты, проверяющие получение списка для инициатора, приглашённого и пустой сценарий. 【F:apps/api/videochat_api/services/rooms.py†L276-L289】【F:apps/api/tests/test_rooms.py†L144-L217】【F:apps/api/README.md†L120-L132】【F:apps/api/knowledge/rooms.md†L1-L37】

## Проверка
- Запустить `pytest` в каталоге `apps/api` (требуются dev-зависимости). 【F:apps/api/README.md†L86-L109】
- Провести ручной сценарий из README: создать комнату, вызвать `GET /rooms/me` под инициатором и приглашённым — убедиться, что список содержит `room_id` и статусы. 【F:apps/api/knowledge/rooms.md†L19-L35】

## Риски и открытые вопросы
- Требуется применение новой Alembic-миграции и актуализация данных в продуктивной БД; необходимо учесть обратную совместимость с существующими комнатами.
- Клиентские приложения должны быть готовы к новому формату ответа (список вместо одиночного объекта); требуется синхронизация с фронтендом.
