## Цель
Реализовать REST-эндпоинт, позволяющий приглашённому другу подтвердить участие в комнате по её идентификатору и перевести статус комнаты из `waiting` в `active`.

## Контекст
- Текущее REST-API комнат покрывает создание, получение статуса, выход и админский список, но не предоставляет способ присоединиться ко второй стороне через HTTP. 【F:apps/api/videochat_api/api/endpoints/rooms.py†L41-L142】
- Сервис `RoomService` уже содержит метод `join_room`, который проверяет дружбу, ограничение в два участника и переключает статус на `ACTIVE`. 【F:apps/api/videochat_api/services/rooms.py†L81-L123】
- `join_room` возвращает флаг изменения состояния и синхронизирован с Redis-кэшем, что позволяет безопасно дернуть его из эндпоинта. 【F:apps/api/videochat_api/services/rooms.py†L113-L125】

## Проблема
При тестировании через Swagger второй пользователь может вызвать только `GET /rooms/{id}` и `GET /rooms/me`, из-за чего комната остаётся в статусе `waiting`, не отображается в списке активных и не может стартовать видеозвонок. Нет REST-операции, аналогичной `POST /friends/accept`, чтобы зафиксировать участие приглашённого.

## Предлагаемое решение
- Добавить маршрут `POST /rooms/{room_id}/join`, завязанный на `RoomStatusResponse`.
- Внутри эндпоинта преобразовать `room_id` к `UUID`, вызвать `RoomService.join_room`, обрабатывать `RoomForbiddenError`, `RoomConflictError` и `RoomNotFoundError` аналогично существующим методам.
- При `changed=True` отправлять через Socket.IO событие `room:user_joined` (или аналогичное) в комнату `video-room:{room_id}` и приглашённому/инициатору, чтобы фронтенд получил обновление статуса.
- Обновить документацию Swagger (описание эндпоинта), если используется `response_model`, и при необходимости дополнить схемы/переводы.
- Добавить pytest-кейс, проверяющий, что приглашённый пользователь переводит комнату в `ACTIVE`, и что повторный вызов не ломает идемпотентность.

## Проверка
- Прогнать `pytest` для убедительности.
- Ручной сценарий в Swagger: пользователь А создаёт комнату, пользователь B вызывает новый `POST /rooms/{room_id}/join`, после чего `GET /rooms/{room_id}`/`GET /rooms/me` возвращают статус `active`, а комната появляется в админском списке.

## Риски и открытые вопросы
- Убедиться, что событие Socket.IO не дублирует уже реализованную логику вебсокетов `RoomNamespace`, чтобы не возникло двойных уведомлений.
- Проверить, что ограничение на число участников остаётся корректным и нет гонок между WebSocket-присоединением и REST-вызовом.
