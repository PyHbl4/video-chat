# Self Prompt: HTTPX и aiosqlite для тестов

## Цель
Исправить падение `pytest` из-за отсутствующих зависимостей (`httpx`, `aiosqlite`, `trio`) и обеспечить успешный запуск тестов для API видео-чата.

## Контекст
- FastAPI+Socket.IO сервис описан в `README.md`: единый жизненный цикл, in-memory SQLite и заглушка Redis в тестах.
- `AGENTS.md` и `knowledge/*.md` подчеркивают, что тесты используют `AsyncClient` из `httpx`, асинхронный SQLAlchemy с драйвером `sqlite+aiosqlite` и AnyIO для смены бэкендов.
- В репозитории уже есть папка `apps/api/httpx/` — локальный аналог клиента для тестов.
- Тестовая конфигурация (`tests/conftest.py`) создает `AsyncEngine` и `AsyncClient`, опираясь на упомянутые зависимости.

## Проблема
- При запуске `pytest` возникает `ModuleNotFoundError: No module named 'httpx'`, потому что стандартный пакет не установлен, а локальная реализация не попадает в `PYTHONPATH`.
- После устранения первой ошибки проявляются аналогичные проблемы с `aiosqlite` и избыточной параметризацией AnyIO (`trio`).
- Без этих зависимостей фикстуры (`engine`, `client`) не поднимаются, поэтому тесты не стартуют.

## Предлагаемое решение
1. Сделать каталог `apps/api/tests` пакетным и добавить его `__init__`, который расширяет `sys.path` (`apps/api`) — так `httpx` и будущая заглушка `aiosqlite` будут импортироваться до установки зависимостей.
2. В `tests/conftest.py` явно ограничить фикстуру `anyio_backend` значением `"asyncio"`, чтобы избежать требования `trio`.
3. Расширить локальный модуль `httpx` — привести `Response.text` к интерфейсу свойства, как в оригинальной библиотеке.
4. Реализовать модуль `apps/api/aiosqlite/`:
   - асинхронные курсор и соединение, работающие через фонового worker-потока;
   - совместимый интерфейс с ожиданиями SQLAlchemy (`__await__`, методы `create_function`, `set_trace_callback` и т.д.).
5. Добавить `tests/__init__` и новый модуль в репозиторий, обновить `pyproject.toml`, если требуется конфигурация Pytest.

## Проверка
- Запустить `pytest tests/test_docs.py` и `pytest -k nothing` в `apps/api` для smoke-проверки импортов.
- После внедрения заглушек тесты должны стартовать без ошибок `ModuleNotFoundError`.

## Риски и открытые вопросы
- Заглушка `aiosqlite` покрывает лишь сценарии тестов; при расширении функциональности или использовании специфических API может потребоваться доработка.
- Необходимо убедиться, что произвольные тесты (`pytest` без фильтров) проходят полностью; если нет — проанализировать взаимодействие с кастомным `pytest_asyncio_plugin`.
