# Инженерные соглашения

Этот документ фиксирует правила работы с backend видеочата на FastAPI. Следуйте им при добавлении новых возможностей, поддержке инфраструктуры и рефакторинге.

## Архитектура
- Входная точка — `videochat_api/main.py`. Функция `create_fastapi_app()` настраивает FastAPI-приложение, включает CORS и подключает маршруты из `videochat_api.api.routes`.
- Lifespan-хендлер инициализирует соединения с PostgreSQL (через `videochat_api.db.session.get_engine`) и Redis (`redis.asyncio.from_url`). Объекты складываются в `app.state` и корректно закрываются при остановке.
- Итоговое ASGI-приложение — `socketio.ASGIApp`, которое оборачивает HTTP-часть Socket.IO-сервером из `videochat_api.websocket.server`. Любые новые middleware и зависимости нужно добавлять в FastAPI-инстанс до создания ASGIApp.
- Версионирование API пока отсутствует: роутер `videochat_api.api.routes` монтирует модули `system` и `auth`. При добавлении новых областей (rooms, calls) подключайте их через этот роутер.

## Код-стайл и зависимости
- Целевая версия Python — 3.11. Используйте современные возможности языка (pattern matching, `typing.Self`, `|`) и типизацию Pydantic v2.
- В проекте применяется Ruff, MyPy и Pytest (см. extras `[dev]`). Поддерживайте чистоту кода: без неиспользуемых импортов, отладочных `print` и закомментированных блоков.
- Конфигурация загружается из `.env` через `videochat_api.config.Settings`. Не хардкодьте URL, секреты и тайминги; расширяйте настройки через Pydantic Settings.
- Любой новый каталог с Python-кодом обязан содержать `__init__.py`, иначе Alembic autogenerate не увидит модели, а импорты сломаются.

## Работа с БД
- Используем SQLAlchemy 2.x с `AsyncSession` и драйвером `asyncpg`. Сессии выдаёт зависимость `get_session_dependency()`.
- При выполнении мутаций всегда вызывайте `await db.commit()` после успеха и `await db.rollback()` в блоке `except`. Не оставляйте открытые транзакции.
- Для выборок `scalar_one_or_none()` и `scalars()` проверяйте результат на `None`/пустой список перед дальнейшим использованием.
- Модели лежат в `videochat_api.models`. Поддерживайте явные `__tablename__`, связи и индексы. После изменения моделей создавайте миграции `alembic revision --autogenerate` и проверяйте дифф.

## Аутентификация и сессии
- За управление токенами отвечает `videochat_api.auth.session.SessionService`. Веб-клиенты получают cookie + CSRF, нативные — пару access/refresh.
- Все токены хешируются перед сохранением. Не храните сырые значения в базе, не передавайте их в логах.
- `videochat_api.dependencies.get_current_user` сначала пытается разобрать bearer-токен, затем cookie. Он записывает `auth_session` и `db_session` в `request.state` — не затирайте эти поля в middleware.
- Ограничение попыток логина реализовано через `RedisRateLimiter`. Без Redis авторизация и восстановление сессий не работают.

## Работа с WebSocket и сигналингом
- Socket.IO-сервер создаётся в `videochat_api.websocket.server`. Он принимает подключения от фронтенда и доступен по пути `/socket.io/`.
- Для новых событий используйте пространство имён по умолчанию. Логика комнат, сигналинга WebRTC и уведомлений должна жить в отдельных модулях и регистрироваться через `sio.on`.
- Не блокируйте обработчики долгими синхронными операциями — используйте асинхронные вызовы или выносите тяжёлую работу в фоновые задания (пока отдельного воркера нет).

## Логи и наблюдаемость
- Используйте стандартный логгер `logging`. Добавляйте структурированные сообщения с контекстом пользователя/сеанса. Не вставляйте `print`.
- При добавлении middleware соблюдайте порядок: метрики и трассировка должны оборачивать пользовательские обработчики, чтобы видеть полный цикл запроса.

## Тестирование
- Интеграционные и модульные тесты размещайте в `apps/api/tests`. Используйте `pytest-asyncio` и фикстуры для `AsyncSession`.
- Покрывайте сценарии аутентификации, ограничения по частоте и WebSocket-взаимодействия. Для Redis можно использовать `fakeredis` или dockerized Redis в CI.

## Процесс разработки
1. Создайте ветку `feature/*` или `fix/*`.
2. Обновите документацию (README, knowledge base) вместе с кодом.
3. Прогоните проверки: `ruff check`, `mypy`, `pytest`. Убедитесь, что Alembic миграции в актуальном состоянии.
4. Перед merge опишите изменения и тесты в PR, приложите инструкции по запуску, если инфраструктура изменилась.

## Особенности и предупреждения
- Redis обязателен для rate limit и cookie-сессий. Обязательно проверяйте подключение при старте.
- CORS в `create_fastapi_app()` ограничен localhost-портами. Если фронтенд запускается на другом origin, расширяйте список.
- Не меняйте форматы ответов Pydantic-схем (`videochat_api.schemas`) без синхронизации с клиентами.
- Для CLI/скриптов используйте `videochat_api.main:main` или `uvicorn` с флагом `--factory` отключённым (ASGIApp уже собран).
- При добавлении новых endpoints продумывайте миграцию сессий: `SessionService` хранит Refresh-токены в базе и связан с устройствами (`videochat_api.models.Device`).
