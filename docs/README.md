# Каталог `.ai_docs`

Цель каталога — собрать внутреннюю документацию по проекту, оформленную в едином стиле и предназначенную для оперативной работы разработчиков и AI-агентов. Здесь фиксируем архитектуру, особенности сервисов, типовые сценарии и доменные понятия.

## Общие принципы
- **Язык**: вся документация ведётся на русском языке, в деловом стиле, с пояснением терминов при первом упоминании.
- **Структура**: один документ — одна логическая тема. Если материал разрастается, выносите подробности в отдельный файл и оставляйте ссылки.
- **Разметка**: формат Markdown, короткие абзацы, заголовки не глубже `###`. Используйте маркированные списки и таблицы для читаемости.
- **Фронтматтер**: в начале каждого файла (кроме `README.md`) добавляем YAML-блок:
  ```yaml
  ---
  title: "Краткое название"
  summary: "В одном предложении, о чём документ"
  updated: YYYY-MM-DD
  owners: ["github-ник"]
  tags: ["область", "технология"]
  related: ["путь/к/другому/файлу.md"]
  ---
  ```
  Поле `related` содержит относительные пути к смежным документам или файлам кода.
- **Ссылки на код**: используйте относительные пути вида `apps/game-api/src/...` с указанием строк, если это критично (`:L42`).
- **Коды и конфиденциальность**: не копируйте приватные ключи, логины и пароли; в примерах заменяйте на заглушки.
- **Проверки**: перед коммитом убедитесь, что фронтматтер валиден (YAML), ссылки работают, а текст укладывается в 1500–2000 символов на логический блок — так проще подавать в промпты.

## Структура каталога
- `overview/` — обзорные материалы по монорепозиторию: архитектура, CI/CD, инфраструктура.
- `apps/` — документация приложений из `apps/`. Каждое приложение — отдельная папка (`apps/<slug>/`).
- `core/` — описание сервисов и библиотек из сабмодуля `core/`.
- `libs/` — документация вспомогательных пакетов из `libs/` (например, [`libs/web-auth`](libs/web-auth/index.md) — про клиент аутентификации для Next.js).
- `howtos/` — операции и пошаговые инструкции (how-to, recipes).
- `glossary.md` — доменные термины и внутренние сокращения.

## Требования к документации сервисов (`apps/`, `core/`, `libs/`)
Каждый сервисный документ (`index.md`) должен содержать разделы:
1. **Назначение** — одна-две фразы, зачем нужен сервис.
2. **Точки входа** — основной стартовый файл/команда, используемые порты, протоколы.
3. **Основные зависимости** — внешние сервисы, базы данных, очереди, библиотеки.
4. **Ключевые модули** — краткое описание важнейших папок/файлов.
5. **Потоки данных / основная логика** — как обрабатываются типовые сценарии.
6. **Конфигурация** — переменные окружения, конфиги, миграции.
7. **Диагностика и отладка** — полезные команды, логи, метрики.
8. **Точки расширения** — куда смотреть, если нужно добавить функциональность.

Дополнительные файлы рядом с `index.md` можно выделять под сложные подсистемы (`matchmaking.md`, `auth-flows.md`) или how-to внутри сервиса (`local-setup.md`). Повторно используемый материал выносите в `overview/` или `howtos/`.

## Процесс обновления и запросы информации
1. **Подготовка**: определите, какой файл нужно обновить/создать. Если нет подходящего файла — заведите новый рядом со схожими материалами.
2. **Сбор данных**: изучите код, логи, задокументированные переменные окружения, историю PR. Если остаются пробелы — сформулируйте вопросы владельцу или в `.tasks`.
3. **Черновик**: заполните фронтматтер (не забывайте обновлять `updated`), перенесите факты из изучения, добавьте ссылки на код.
4. **Проверка**: перечитайте текст на понятность для «холодного» читателя (агента), убедитесь, что в документе есть контекст и шаги для воспроизведения.
5. **Связи**: добавьте ссылки в смежных документах (например, из `AGENTS.md` или других сервисов) на новый материал.

Если информации недостаточно:
- Зафиксируйте известные факты и список открытых вопросов в разделе "Заметки" или отдельном блоке "Открытые вопросы".
- Отметьте в `tags` значение `needs-input` и создайте задачу в `.tasks` с просьбой закрыть пробелы.

## Взаимодействие с `AGENTS.md`
В `AGENTS.md` хранится высокоуровневая навигация. При добавлении новой секции здесь добавляйте соответствующую ссылку в `AGENTS.md` (например, раздел "Документация" → `.ai_docs/README.md`).

## Поддержка единого стиля
- Используйте одинаковые заголовки для повторяющихся разделов.
- Параграфы до 3–4 предложений, избегайте канцеляризмов и англицизмов без пояснения.
- Для перечислений — маркированные списки; для последовательностей — нумерованные.
- Сложные термины отмечайте курсивом и ссылайтесь на `glossary.md`.

Соблюдение этих правил позволит быстро адаптировать материалы под запросы AI-агентов и поддерживать документацию в актуальном состоянии.
