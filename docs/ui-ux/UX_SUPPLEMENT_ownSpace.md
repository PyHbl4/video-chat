# Дополнения к UX-стратегии ownSpace

## 1. Политика состояний

Единые правила для интерфейсов загрузки, ошибок и пустых состояний:

- **Loading** — скелеты списков (Friends, Chats, Calls), в Call: баннер «Подключение…».
- **Empty** — поясняющий текст + CTA («Добавьте контакт», «Создайте чат»).
- **Error** — баннер вверху + toast (без стек-трейсов).
- **Retry** — кнопка «Повторить» на баннере.
- **Incoming Call** — toast + модальное окно; toast приоритетнее системных диалогов.

## 2. Навигация и хоткеи

Полная навигация с клавиатуры (Tab-порядок, видимый фокус).  
Поддерживаемые сочетания клавиш:

| Действие | Клавиша |
|-----------|----------|
| Микрофон вкл/выкл | `M` |
| Камера вкл/выкл | `V` |
| Демонстрация экрана | `S` |
| Завершить звонок | `E` |
| Закрепить участника | `P` |
| Перейти в аудио-режим | `A` |
| Принять входящий звонок | `Enter` |
| Отклонить звонок | `Esc` / `Backspace` |

**A11y:**  
`role="dialog"`, `aria-labelledby`, `aria-describedby`, `aria-live="polite"` для уведомлений.  
Поддержка `prefers-reduced-motion` и контрастности по WCAG AA.

## 3. Сетка звонков

- 1 участник: 1×1, центр.
- 2 участника: 1×2.
- 3–4 участника: 2×2.
- 5–6 участников: 2×3 (desktop), 3×2 или 2×3 (mobile).
- Закреплённый участник увеличен, остальные равномерно вокруг.
- На мобильных — закреплённый сверху, мини-видео снизу (карусель).

## 4. Уведомления

Используем библиотеку **sonner**.

- Макс. 2 активных уведомления одновременно.
- Длительность ≤ 3 сек.
- Без звука, кроме входящего звонка.
- Слабая сеть → баннер в Call с кнопкой «Только аудио».

## 5. Темы и токены (брендинг)

**Текущие темы:** светлая / тёмная, акцент — бирюзовый `#10B981`.

Пример токенов:

```css
:root {
  --bg: #ffffff; --fg: #0a0a0a;
  --muted: #6b7280; --card: #f6f7f8;
  --accent: #10b981;
  --danger: #ef4444; --warning: #f59e0b; --success: #22c55e;
  --radius: 14px; --shadow: 0 8px 24px rgba(0,0,0,0.08);
}
.dark {
  --bg: #0a0a0a; --fg: #f5f5f5;
  --muted: #9aa0a6; --card: #111214;
  --accent: #10b981;
}
```

> Для self-hosted клиентов можно предусмотреть `brand.json` с переопределением токенов (цвета, радиусы, тени) без изменения кода.

## 6. Настройки и синхронизация

**MVP:**
- Хранение настроек локально (`localStorage`): тема, последний таб, mute, раскрытие сайдбара.
- Сервер управляет доступностью звонков и блок-листом (в будущем).

**Далее:**
- Таблица `user_preferences` в БД.
- Мердж предпочтений по timestamp: при конфликте выбирается последнее изменение.

## 7. Поиск

**MVP:**  
Пустое поле в Friends/Chats (только UI, без запросов).

**Следующий шаг:**  
Реальный поиск `/app/search/users` с пагинацией и кнопкой «Добавить в друзья».

**Будущее:**  
Единый `/app/search/all` с вкладками Users / Chats / Files (заготовка маршрутов уже сейчас).

## 8. Производительность UI

- Избегать перекрытий: модалки компактные, toolbar звонка всегда доступен.
- Мемоизация компонентов, виртуализация списков (Friends, Chats).
- Дебаунс поиска — 300 мс.
- Ленивые контролы (DeviceSelector — вне DOM до вызова).
- Контрастность акцента проверять на фоне, не использовать большие заливки.

## 9. Definition of Done (UX-этап)

- Все разделы навигируются клавиатурой.
- Скелеты загрузки реализованы в Friends / Chats / Calls.
- Call-экран с сеткой, закреплением и toolbar’ом.
- Входящий звонок: toast + модал, параллельный звонок: баннер.
- Переключение темы без перезагрузки.
- Логотип `OwnSpaceLogo` корректно инвертируется по теме.
- Документированы сценарии тестирования: desktop и mobile.

## 10. Комментарии к открытым вопросам

- **Бренд-кастомизация:**  
  Цветовая схема (light/dark + бирюзовый) утверждена.  
  Для кастомизации — токены или `brand.json`.  
  Логотип реализован компонентом React (`apps/web/components/logos/main-logo.tsx`) с пропсами `color` и `accent`.

- **Синхронизация настроек:**  
  Пока локально, в дальнейшем через `user_preferences` на сервере.

- **Расширенный поиск:**  
  Визуально присутствует, позже получит бэкенд-маршрут `/app/search/users`.  
  Зарезервировать хедер с табами (Users / Chats / Files) на будущее.
