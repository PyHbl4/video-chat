# ownSpace — UI Skeleton Stage 2 (Friends)

## Цель

Улучшить визуальную иерархию и читабельность, довести страницу «Друзья» до состояния близкого к production-UI, не меняя бизнес-логику. Поддержать адаптивность, тёмную/светлую темы и сохранить все базовые UI-компоненты в `components/ui`.

## Контекст

Стек: Next.js 15, TailwindCSS, shadcn UI.
Активная страница: `/app/friends` (уже есть Sidebar, Topbar, маршруты и базовый список друзей).
Важно: не удалять и не переименовывать существующие файлы навигации и базовые UI-компоненты.

## Обязательные требования

1. Сохранить все компоненты в `components/ui` без удаления/слияния.
2. Не менять существующие маршруты и layout-структуру.
3. Внести правки только по визуальной иерархии, состояниям и компонентной структуре страницы «Друзья».
4. Обеспечить корректную работу в светлой и тёмной темах.
5. Не добавлять внешние зависимости.

## Визуальная иерархия (страница «Друзья»)

— Ввести явные вертикальные секции: Заголовок/действия → Поиск → Фильтры → Список.
— Увеличить отступы между секциями (section spacing), внутри секций — единая сетка (8-pt).
— Ограничить ширину контента (`max-width` контейнера) и выровнять по центру.
— Выделить визуально активную область (список друзей), вторичный текст сделать приглушённым.
— Заголовок страницы крупнее подзаголовка; подзаголовок короче и мягче по контрасту.

## Структура страницы (целевое расположение)

1. Верхняя панель страницы:
   — Заголовок «Друзья» и краткий подзаголовок (1 строка).
   — Блок действий справа: «Новый чат» и «Запланировать звонок» (горизонтально, одинаковой высоты).
2. Поиск:
   — Однострочный Input с иконкой поиска слева и понятным placeholder.
3. Фильтры:
   — Tabs «Все / Онлайн / Оффлайн», активный таб визуально выделен.
   — Анимация смены таба (лёгкая, без больших длительностей).
4. Список друзей:
   — Единая карточка «FriendCard» для каждого пользователя (см. ниже).
   — Единые отступы и выравнивание по сетке.
5. Пустое состояние / загрузка / ошибка:
   — Пустое: краткая фраза, призыв воспользоваться поиском или отправить приглашение.
   — Загрузка: скелетоны карточек друзей.
   — Ошибка: компактный блок с текстом и кнопкой повтора.

## Компонент FriendCard (базовая спецификация без кода)

Назначение: единый элемент списка друзей.

Состав (слева направо):
— Аватар фиксированного размера.
— Текстовая колонка: Имя (жирное), Роль/описание (вторичный стиль), Статус.
— Правая колонка действий: «Позвонить» (первичное), «Профиль» (вторичное), «Удалить» (опасное действие — подтверждение через диалог в будущем).

Состояния:
— online: статус с акцентным цветом;
— offline: статус приглушённый;
— hover/focus: лёгкая тень/обводка в стиле shadcn;
— disabled: приглушение интерактивных элементов по UX-гайдам.

Адаптив:
— Desktop: три колонки (аватар/текст → пустое пространство → действия).
— Mobile: стек вертикальный (аватар/текст сверху, действия снизу в одну строку или две, без переполнений).

## Фильтры и поведение списка

— Переключение табов динамически обновляет список (на уровне UI — визуальная смена; источники данных не менять).
— На каждом табе должны работать состояния загрузки/пусто/ошибка.
— При активном поиске таб остаётся выбранным, список фильтруется дополнительно.

## Поиск и действия

— Поиск: иконка лупы, понятный placeholder, корректные отступы.
— Кнопки действий на странице: одинаковая высота, единый визуальный стиль и состояние hover/focus.
— На мобильных кнопки действий переносятся под заголовок и идут в одну строку с переносом (или стекаются).

## Layout и сетка

— Контейнер контента ограничен по ширине и центрирован.
— Единые отступы: внешние секции крупнее, внутренние — меньше.
— Sidebar и Topbar не менять. Topbar: показывать заголовок активной страницы.

## Цветовые токены и тема

— Использовать существующие дизайн-токены: primary, secondary, muted, accent, destructive.
— Проверить контраст для текста и интерактивных элементов в обеих темах.
— Статусы online/offline — различимы по цвету и насыщенности, текст читается в обеих темах.

## Доступность

— Фокус-состояния у всех интерактивных элементов.
— У аватаров альтернативный текст.
— Контрасты текста и иконок достаточные по WCAG AA.
— Кнопки действий имеют aria-label при необходимости.

## Проверки (Acceptance Criteria)

— Визуальная иерархия: секции различимы, страница «дышит», главная доминанта — список друзей.
— FriendCard единообразен, без визуальных скачков по высоте/отступам; кнопки действий выровнены.
— Tabs визуально активен, есть анимация, состояния списка (loading/empty/error) реализованы.
— Поиск выглядит как цельный элемент с иконкой, не «пляшет» на разных размерах.
— Адаптивность: мобильная/десктопная вёрстка без переломов и горизонтальной прокрутки.
— Тема: в темной/светлой всё читается, контраст достаточный.
— Никаких новых зависимостей, всё рендерится через `pnpm dev` без ошибок.

## Что не делать

— Не менять маршруты, файлы layout и общую навигацию.
— Не переносить/не удалять компоненты из `components/ui`.
— Не добавлять новые библиотеки и глобальные CSS-ресеты.
— Не трогать бизнес-логику и источники данных.

## Результат

— Обновлённая страница `/app/friends` с улучшенной иерархией, состояниями и единым компонентом FriendCard.
— Визуально чистый, адаптивный прототип, готовый к следующей итерации (микро-анимации, диалоги подтверждения, контекстные меню).
